# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Monzoid: домашний учёт по фондам в виде Telegram Mini App. Интерфейс, ошибки API и комментарии в коде на русском. Правила учёта для пользователя описаны в `README.md`.

## Команды

Нужен Node.js 22.13 или новее (встроенный `node:sqlite`). Код под git (локально, без удалённого репозитория): перед каждой выкладкой коммит, откат через `git revert` и повторную выкладку.

```bash
npm install
npm run build        # сборка web в web/dist, её раздаёт сервер
npm start            # сервер на tsx, порт 3000
npm run dev:server   # сервер с перезапуском
npm run dev:web      # Vite
npm test             # все тесты (vitest, server/test/app.test.ts)
npm test -w server -- -t "начисление участнику"   # один тест или группа по имени
npm run typecheck    # server и web; линтера нет
```

- Тесты на настоящих выписках запускаются, только если заданы `KASPI_PDF` и `FREEDOM_PDF`, иначе они пропускаются. Выписки лежат вне репозитория.
- Локальный вход без Telegram: `DEV_AUTH=1`, `OWNER_TELEGRAM_IDS=1`, адрес `http://localhost:3000/?devUser=1`. Конфигурация запуска для превью: `monzoid-dev` в `.claude/launch.json`. `devUser` уходит в заголовок `X-Dev-User`, в production он отключён.
- Выкладка: `bash deploy/deploy.sh root@<сервер>` (адрес в `CLAUDE.local.md`). Скрипт собирает проект на сервере и перезапускает сервис, `.env` и база остаются.

## Архитектура

npm workspaces: `server` (Fastify 5, TypeScript через tsx без сборки, zod) и `web` (React 19, Vite, цвета из темы Telegram через CSS-переменные). Роутера нет: навигация это состояние в `web/src/App.tsx`.

**Сервер (`server/src`)**
- `app.ts`: все маршруты. `access()` проверяет участника базы и на каждый запрос вызывает `syncCredits`.
- `domain.ts`: расчёты. `buildReports` строит все месяцы от `start_ym` накопительно и ничего не хранит, поэтому итоги нельзя править отдельно от операций. Там же закрытие месяцев, темп трат, долги, начисления и слияние виртуальных участников.
- `imports.ts` и `statements/`: разбор PDF (`parse.ts`, позиционно через pdfjs, со сверкой с итогами банка), подсказки действий (`classify.ts`), подсказки фонда и тегов от Haiku (`ai.ts`). В учёт попадает только подтверждённое человеком в `applyDecisions`. Черновик проверки хранится в `import_batches.draft` (автосохранение), выписка отправляется только целиком, `revertImport` возвращает отправленную в черновик.
- `bot.ts` и `queue.ts`: бот принимает PDF-выписки в личке (опрос `getUpdates`, запускается из `index.ts`, если задан `BOT_TOKEN`; `BOT_POLLING=0` выключает). Файл сразу разбирается, в `statement_queue` идут только операции. Если у человека несколько незаблокированных баз, бот спрашивает кнопками. В приложении «Обработать» (`POST /queue/process`) превращает всю очередь человека в обычную выписку на проверку.
- `market.ts`: курсы Нацбанка РК (все пары через тенге) и котировки Yahoo, обновление раз в сутки, цены вкладов по месяцам в `pot_prices`.
- `tags.ts`: теги и статистика по ним.
- `db.ts`: схема и миграции. Новые колонки добавляются через проверку `PRAGMA table_info` в `openDb`.

**Клиент (`web/src`)**: `back.ts` управляет кнопкой «Назад» Telegram, свайпом и предупреждением о несохранённом (`useBack` с глубиной, `useUnsaved`). `format.ts` хранит символ основной валюты текущей базы в модульной переменной.

## Правила, которые легко нарушить

- **Суммы** хранятся целыми в сотых долях основной валюты (тиыны). Возврат это расход с отрицательной суммой.
- **Записи не удаляются.** `entries`, `settlements`, `adjustments`, `members`, `tags` получают `inactive_at`. Любой новый запрос к этим таблицам должен фильтровать `inactive_at IS NULL`, иначе неактивные записи попадут в расчёты.
- **Заблокированная база** (`ledgers.locked`): `access()` отклоняет любой не-GET запрос, кроме PATCH самой базы, и не вызывает `syncCredits`. Новый маршрут записи должен идти через `access()`.
- **Закрытые месяцы** менять нельзя без согласия на пересчёт: `assertWritable` отвечает 409, клиент через `withRecalc` спрашивает и повторяет запрос с `recalc`. Такие изменения пишутся в `closed_changes` (`changes.ts`: `snapshot` до и после, `logChange`), их можно откатить. Месяцы закрываются строго по порядку. История в статистике строится только по закрытым месяцам; исключение «Капитал»: незакрытые прошлые месяцы там видны серыми строками («не закрыт»), а текущий строкой «сейчас».
- **Свободные средства** = доходы − план + корректировки − переводы во вклады. Остаток фонда (план − факт) копится в фонде и в свободные не входит.
- **Вклады** забирают из свободных вложенную сумму, а в итоге считаются по количеству на конец месяца и цене этого месяца. Зафиксированные цены прошлых месяцев не перезаписываются.
- **Активы** (вклад `kind = 'asset'`: недвижимость, машины): покупка и продажа это `pot_moves`, а не доходы и расходы, количество 1 или 0 ставит сервер. Стоимость берётся из последней оценки `asset_values` на конец месяца, без оценки равна уплаченному. Оценки не правятся, только добавляются или снимаются через `inactive_at`, в закрытом месяце пишутся в журнал. В итогах активы отдельно (`assetsAfter`), `moneyAfter` без них.
- **Долг базы** перед участником = его расходы (`paid_by`) − выплаты. Минус это переплата. Доход к человеку привязывает отдельное поле `earned_by`, на долг оно не влияет.
- **Виртуальные участники** имеют отрицательный ID. При новой ссылке на пользователя добавь её в список в `mergeVirtualMember`.
- **Начисления** (`auto_credit = 1`) следуют за планом фонда и вручную не правятся.
- **Личный фонд** участника задаётся явно (`funds.owner_user_id`, один на участника). Начисления (`credit_user_id`) идут только в личный фонд; при смене личного фонда сервер снимает их со старого (`setFundOwner`).
- **В Anthropic** уходят только названия продавцов из покупок и платежей, без номеров. Переводы с именами людей не отправляются (`isAiEligible`).

## Сервер

VPS на Ubuntu за Caddy. Приложение в `/opt/monzoid`, база и копии в `/var/lib/monzoid` (сервис `monzoid`, копии раз в сутки, лимит 128 МБ; копия в gzip уходит владельцам из `OWNER_TELEGRAM_IDS` в Telegram по расписанию из «Ещё → Копии базы», `backup.ts`, по умолчанию раз в неделю). Адрес сервера и его особенности в `CLAUDE.local.md` (не в git).

- Секреты лежат только в `/opt/monzoid/.env`. Пользователь вносит их на сервере сам, в чат они не передаются и не выводятся.
- Перед ручным изменением данных на сервере делай копию через `VACUUM INTO` в `backups/` с именем не на `monzoid-`, такие файлы автоочистка не трогает.
- Клиент в Telegram может показывать старую версию, пока приложение не закрыто полностью.
